# 지금 실행하는 로컬 모의 결제 테스트

백엔드 메뉴 API가 HTTP 500이어도 기존 화면에서 메뉴 담기 → 주문 생성 → TEST 승인 → 영수증까지 눌러 볼 수 있는 별도 로컬 환경입니다. 실제 백엔드 또는 토스 결제 승인 성공을 확인하는 테스트는 아닙니다.

```sh
npm run dev:mock
```

접속: http://127.0.0.1:5174

1. 클래식 버거에서 `담기`를 누릅니다. 옵션이 필요하면 `메뉴 정보 · 옵션`을 펼쳐 선택합니다.
2. 상단 `장바구니` → `결제하기`를 누릅니다.
3. 결제 화면에서 주문 준비가 끝나면 `결제하기`를 누릅니다.
4. KDS 화면 위쪽의 `결제가 완료되었습니다.`와 `MOCK-`로 시작하는 주문번호·금액을 확인합니다.

로그인 없이 영수증까지 확인할 수 있습니다. 일반 화면과 같이 최종 결제 버튼은 하나입니다. 이 환경은 토스 키를 비워 외부 위젯 요청을 시작하지 않으며, 토스 인증창과 실제 서버 승인을 검증하는 환경은 아닙니다.

## 분리 방식

- 기존 `npm run dev`와 `.env.local`, 배포 연결 설정, App/CSS는 변경하지 않습니다.
- 모의 프론트는 127.0.0.1:5174, 모의 API는 임의의 loopback 포트에서만 열립니다.
- API·AI·WS 전달 대상은 모두 로컬입니다. 알 수 없는 API를 실제 서버로 넘기는 fallback이 없습니다.
- 메뉴 번호와 가격은 이 환경만의 예시 데이터입니다. 주문·승인은 프로세스 메모리에만 남으며 서버를 종료하면 없어집니다.
- 브라우저 탭 제목은 `로컬 모의 결제 | DKU Voice`입니다. 정상 결제 화면에 별도 테스트/과금 안내 배너를 추가하지 않았습니다.
- 매 실행마다 모의 서버 ID가 바뀝니다. 별도 테스트 출처에서만 이전 모의 checkout 기록을 정리하므로 다른 서버 실행의 영수증을 재사용하지 않습니다.
- KDS 직원 로그인·관리자·음성·AI 분석은 모의 구현 범위가 아닙니다. 주방 전체 목록은 제공하지 않으며 결제 후 상단 영수증까지만 확인합니다.
- `TEST/CARD`만 승인하며 TOSS, 잘못된 금액·옵션, 같은 주문 재승인은 거부합니다.

다른 포트를 쓰려면 `MOCK_FRONTEND_PORT=5175 npm run dev:mock`처럼 실행합니다. 종료는 실행한 터미널에서 Ctrl+C입니다. 이 주소는 해당 Mac에서만 접속할 수 있으며 팀원의 PC에서는 저장소를 받은 뒤 같은 명령으로 실행해야 합니다.

검증은 `tests/local-mock-payment.test.js`에서 실제 로컬 HTTP와 Vite 프록시를 사용합니다. 메뉴/옵션→장바구니→주문→TEST 승인→PAID 영수증, 잘못된 금액/TOSS/중복 거부, 로컬 요청 제한, 별도 환경 설정을 확인합니다. 실제 카드 인증이나 전체 브라우저 클릭을 자동 검증한 것은 아닙니다.

이 테스트 실행 기능은 프론트 PR의 변경 사항에 포함됩니다. 실제 배포 환경의 결제 승인 검증은 별도입니다.
