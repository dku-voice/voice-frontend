# 카메라 나이 분석 연결 — 2026-11-19

## 구현 범위와 남은 조건

카메라 미리보기, 사용자가 요청한 사진 한 장의 전송, AI 추정값 표시, 취소·오류·자원 정리, 명시적인 터치 주문 선택을 구현했습니다. 기존 다국어 상태와 화면 이동 구조를 재사용합니다.

**나이에 따른 자동 터치모드 전환은 구현하지 않았습니다.** 사용자에게 전달된 팀 전환 정책이 없기 때문입니다. `is_senior`는 받아서 보존하지만 터치모드나 고대비 설정을 변경하는 명령으로 사용하지 않습니다. 추정값은 실제 나이의 확인이나 주문 접근 제한에 사용하지 않습니다.

## 기존 코드 분석

- 카메라는 `App.jsx`의 `captureSnapshot()`에서 실행했습니다. 환경변수 주소로 multipart `snapshot`을 전송하고 HTTP 성공 여부만 확인했습니다. 나이 분석 JSON을 읽지 않았고, 영상 크기가 없으면 임의 크기로 대체했습니다.
- 음성 지연 뒤 메뉴 화면을 터치하면 전역 `pointerdown`에서 촬영할 수 있었습니다. 이번에는 일반 주문 터치와 촬영 의사를 분리했습니다. 지연 뒤에도 터치 주문은 가능하며 카메라는 별도로 선택합니다.
- 연령 추정값이 갱신되면 화면을 강제로 연령 화면으로 이동하는 effect가 있었습니다. 이를 제거하여 주문·결제나 사용자가 선택한 화면을 가로채지 않게 했습니다.
- 중앙의 별도 주문 모드 객체는 없습니다. 음성을 중지하고 메뉴 화면의 버튼으로 주문하는 기존 방식이 터치 주문입니다. 새 모드 시스템을 추가하지 않았습니다.
- 기존 WebSocket 주문 파싱, language 처리, 한국어 5초 안내/외국어·미확인 12초 응답 대기는 재사용합니다. 카메라를 이 타이머에서 자동 실행하지 않습니다.

## 확인한 실제 API 규격

2026-11-19 실제 배포 서버의 [OpenAPI](https://dku-voice.com/ai/openapi.json)를 GET으로 확인했습니다(HTTP 200, Voice AI Server 2.0.0). 경로에 GET을 보냈을 때 405도 확인했지만, 이미지 POST나 실제 AI 추론은 실행하지 않았습니다.

| 항목 | 확인한 내용 |
|---|---|
| 배포 요청 | `POST /ai/api/vision/analyze_age` |
| 요청 본문 | `multipart/form-data`, 필수 `file` 하나(이미지 파일) |
| 응답 | 주문 API의 공통 envelope가 아닌 최상위 `status`, `estimated_age`, `age_group`, `is_senior`, `error_msg` |
| 상태 | `status: "success"` 또는 `"error"`. HTTP 200이라도 error면 분석 실패 |
| 나이 | `estimated_age`: 정수 또는 null, 필수 항목은 아님 |
| 분류 | `age_group`: child/adult/senior/unknown, 기본 unknown |
| 표시 힌트 | `is_senior`: boolean, 기본 false |
| 오류 | `error_msg`: 문자열 또는 null. 원문을 사용자 화면이나 로그에 보관하지 않음 |
| 기타 응답 | HTTP 422 문서화. 그 밖의 HTTP 실패도 안전한 오류로 처리 |

연관 소스는 확인 당시 커밋을 고정해 비교했습니다: [vision API](https://github.com/dku-voice/voice-ai-server/blob/bfdee3e938cf2c9db62dc8b9014d63d5a97416a7/app/api/vision.py), [응답 스키마](https://github.com/dku-voice/voice-ai-server/blob/bfdee3e938cf2c9db62dc8b9014d63d5a97416a7/app/schemas.py), [분석 서비스](https://github.com/dku-voice/voice-ai-server/blob/bfdee3e938cf2c9db62dc8b9014d63d5a97416a7/app/services/vision_service.py), [설정](https://github.com/dku-voice/voice-ai-server/blob/bfdee3e938cf2c9db62dc8b9014d63d5a97416a7/app/config.py).

소스는 JPEG/JPG/PNG/WebP를 지원하며 기본 용량 제한은 5MiB, 디코딩 픽셀 제한은 6백만입니다. 이는 소스 기본값이며 **실제 배포 환경변수 설정값을 확인한 것은 아닙니다.** 프론트는 보수적으로 5MiB까지만 허용하며, 실제 촬영은 JPEG·최대 1280×720·원본 비율 유지로 제한합니다. 성공 나이는 소스와 맞춰 정수 0~120인지 검사합니다. 성공 응답에 나이가 없거나 null이면 임의 숫자 대신 분석 실패를 안내합니다.

OpenAPI에는 해당 연산의 인증 요구가 정의되어 있지 않습니다. 주문 API의 JWT나 쿠키를 임의로 붙이지 않습니다. 같은 출처의 `/ai` 상대경로와 이미 있던 Vite 개발 프록시를 사용하며 Nginx·Docker·서버 설정을 변경하지 않았습니다. 기존 `VITE_AI_SNAPSHOT_URL`은 이 분석에서 사용하지 않습니다.

## 화면 및 자원 처리

1. 메뉴의 카메라/연령 버튼으로 기존 연령 화면을 엽니다. 화면 진입만으로 권한을 요청하지 않습니다.
2. 사진 전송 안내를 확인하고 **카메라 켜기**를 누르면 비디오 권한만 요청하고 미리보기를 보여줍니다. 마이크를 요청하거나 이미지를 전송하지 않습니다.
3. **촬영 후 분석**을 눌러야 한 프레임을 캡처해 `file`로 전송합니다. 영상이 준비되지 않았거나 장치가 끊겼으면 전송하지 않습니다.
4. 촬영 직후 트랙을 중지하고 video·canvas를 비운 뒤 서버 결과를 기다립니다. 추정값을 표시하며 모드를 자동 변경하지 않습니다.
5. **터치로 주문하기**를 직접 누르면 카메라를 취소하고 기존 메뉴 화면으로 돌아갑니다. 고대비도 기존 버튼으로 직접 선택합니다.

- 연속 열기/분석 클릭은 진행 중인 Promise를 공유하여 중복 촬영·요청을 방지합니다.
- 권한 응답 최대 15초, 미리보기 시작/캡처 각각 최대 10초, 분석 요청·응답 읽기 최대 30초입니다. 이 시간은 카메라 작업용이며 음성의 5초/12초 기준을 변경하지 않습니다.
- 권한 거부, 미지원 환경, 장치 없음/사용 중/연결 종료, 미준비 영상, 캡처 실패, 네트워크·HTTP·JSON·분석 실패를 안내합니다. 카메라 실패가 메뉴·장바구니·결제 사용을 잠그지 않습니다.
- 취소·다른 화면 이동·페이지 숨김/이탈·앱 종료 시 스트림/예약/요청을 정리합니다. 브라우저의 권한 대화상자 자체는 강제로 닫을 수 없지만, 취소 후 늦게 허용된 스트림은 즉시 중지합니다.
- 요청 세대와 AbortSignal을 사용해 이전 권한 허용, play/toBlob 완료, 서버 응답이 새 화면이나 결과를 바꾸지 못하게 합니다. 업로드 직전에도 현재 화면·음성·결제 상태를 확인합니다.
- 음성 시작/분석 대기 중에는 카메라 진입을 막고 중지 안내를 표시합니다. 음성이나 결제 작업이 시작되면 카메라를 취소합니다. 카메라 결과는 음성 타이머를 완료시키지 않습니다.
- 기존 AI 추천 메시지가 와도 카메라 화면을 자동으로 벗어나지 않습니다. 추천 데이터 자체의 갱신은 유지합니다. 무시하는 기존 연령 이벤트가 음성 응답 타이머를 해제하지 않도록 했습니다.
- 얼굴 이미지는 컴포넌트 상태·localStorage·파일·감사 로그에 보관하지 않습니다. 캡처 Blob은 한 번의 분석에만 사용합니다. 이미 전송된 데이터를 브라우저의 취소로 서버에서 회수할 수는 없으며, 서버의 보관·로깅 정책은 담당자 확인이 필요합니다.

## AI 담당자와 함께 확인할 사항

- 실제 정상/실패 JSON 예시, 운영 인증 요구, 이미지 용량·해상도·MIME 제한, 초기 모델 준비 시간과 권장 제한 시간
