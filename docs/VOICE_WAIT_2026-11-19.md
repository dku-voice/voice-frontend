# 음성 대기·터치 대체 시간 개선 — 2026-11-19

## 기존 동작과 문제

- 실제 전송 경로는 AudioWorklet의 Float32 프레임 → 노이즈 워커의 16kHz mono Int16 PCM → `sendAudioToServer()` → WebSocket입니다.
- 기존 타이머는 **첫 PCM 전송부터** 3초/5초 또는 12초를 셌습니다. 서버의 분석 시작 신호를 받은 것이 아니므로 녹음 길이가 응답 대기 시간에 섞였습니다.
- 기본 화면이 한국어면 아직 발화 언어를 모르더라도 5초 안내가 실행됐습니다. 기존 5초 처리는 강제 화면 이동이 아니라 지연 안내/터치 스냅샷 플래그였으며, 음성 결과 처리를 막지는 않았습니다.
- 기존 대기는 12초 후에도 끝나지 않았습니다. 언어만 포함된 JSON도 결과 완료로 간주해 대기 표시가 일찍 사라질 수 있었습니다. 종료된 녹음의 지연 결과는 언어만 보호하고 주문 내용은 계속 반영할 여지가 있었습니다.

## 현재 시간 기준

| 상황 | 동작 |
|---|---|
| 음성 연결 준비 | 인식 대기와 별도로 WebSocket open을 최대 5초 기다림. 중단·오류 시 예약/리스너 정리 |
| 로컬 발화 활동이 계속됨 | 녹음 단계. 5초/12초 분석 대기 타이머를 실행하지 않음 |
| 약 800ms 무음 | 로컬 추정 발화 종료 후 응답 대기를 시작 |
| 처음부터 무음만 수신 | 첫 무음부터 응답 감시를 시작해 무응답 상태를 계속 기다리지 않음 |
| 응답 대기 3초 | 기존 로딩 피드백 표시 |
| 한국어를 직접 선택했거나 현재 응답에서 ko가 확인됨 | 대기 5초에 터치 대체 안내. **현재 음성 요청은 취소하지 않음** |
| 일본어·스페인어·태국어 선택 또는 발화 언어 미확인 | 5초 안내를 하지 않고 12초까지 기다림 |
| 응답 대기 12초 | 요청 만료. 마이크/예약 타이머/해당 소켓 정리, 터치 주문·음성 재시도 안내 |

한국어 5초에도 즉시 요청을 취소하면, 실제로는 외국어였고 language가 6~9초 결과와 함께 오는 경우를 보호할 수 없습니다. 따라서 5초는 기존 의미인 **터치 대체 안내**로 유지하고, 결과는 12초 만료 전까지 받습니다. 이때 카메라를 열거나 화면을 강제로 바꾸거나 TTS로 발화를 방해하지 않습니다. 터치 메뉴와 장바구니는 계속 사용할 수 있습니다.

기본/저장된 한국어 **화면 언어**를 이번 발화의 확정 언어라고 보지 않습니다. 명시적 언어 버튼 선택이 없으면 미확인 기준인 12초를 적용합니다. 한국어 버튼을 다시 선택하면 같은 화면 언어라도 5초 기준을 적용합니다. 정상 language를 수신하면 기존 자동 UI 전환을 유지하며 현재 응답의 대기 기준에도 반영합니다.

언어를 바꾸면 예전 예약을 취소하고 경과 시간에 맞춰 다시 예약합니다. 같은 대기 요청의 시작 시각/12초 한도는 연장하지 않으므로 반복 클릭으로 무한 대기하지 않습니다. 다시 말하기 시작하면 녹음 단계로 돌아가고, 새 무음 구간 뒤의 응답 대기를 시작합니다.

## 녹음과 서버 분석의 구분 및 한계

현재 확인된 프로토콜에는 배포 서버가 분석을 시작/종료했다고 알려주는 명세가 없습니다. 이를 추측해 stage/progress/END 메시지를 추가하지 않았습니다.

기존 송신 PCM의 RMS가 0.01 이상인지 로컬에서 확인하고, 마지막 활동 후 800ms를 발화 휴지로 봅니다. **이는 가벼운 UI 대기용 추정이며 서버 VAD/분석 시작 시각의 증명이 아닙니다.** 실제 AI 소요 시간의 정확한 측정이라고 보고하지 않습니다. PCM 바이트는 변경하지 않고, 새 API나 음성 모델도 추가하지 않았습니다.

조용하거나 약한 발화, 말 사이의 긴 쉼, 매장 배경 소음에서 이 기준은 실제 마이크로 조정/검증해야 합니다. 계속 큰 소음/발화가 감지되는 구간은 녹음 단계로 남습니다. 이 경우에도 터치 주문과 음성 중지는 가능하며, **12초 한도는 응답 대기에 대한 한도이지 전체 녹음 길이 제한이 아닙니다.** 실제 발화 종료/분석 시작 이벤트를 서버에서 제공할 수 있는지 확인하면 더 정확하게 연결할 수 있습니다.

## 응답과 종료 처리

- `language`만 온 것은 분석 완료의 증거가 아니므로 화면/대기 기준만 갱신합니다. 기존 `type: order`/`item` 등의 정상 결과가 오면 대기를 끝내고 원래 처리로 전달합니다. 확인되지 않은 status/items 등의 새 주문 구조를 임의로 구현하지 않았습니다.
- language가 없거나 잘못된 값이어도 정상 기존 주문은 반영합니다. 알려진 order 이벤트에서 item 자체가 잘못됐거나 JSON이 깨졌으면 오류 안내와 재시도를 가능하게 합니다.
- 12초 만료, 명시적 음성 중지, 이전 미확정 음성을 대체하는 재시작에서는 소켓을 분리합니다. 이전 핸들러가 이미 이벤트 큐에 있어도 현재 소켓인지 검사하므로 만료 결과가 메뉴·장바구니·추천/연령 화면을 바꿀 수 없습니다. 새 시도는 새 연결을 준비합니다.
- 연결 오류/닫힘 시 녹음과 로딩·타이머를 정리하고 기존 오류 및 재연결 흐름을 유지합니다. 연결 대기는 인식 대기와 별도의 취소 가능한 제한으로 관리합니다.
- 노이즈 워커에는 녹음 세대 표식만 로컬로 왕복시킵니다. 종료된 녹음 프레임이 늦게 돌아와 새 요청에 섞이는 것을 막습니다. AI 서버로는 기존 Int16 바이너리만 보내고 표식/요청 ID/새 JSON 필드는 전송하지 않습니다.
- 만료되지 않은 같은 연결 안에서 요청/응답을 정확하게 구분하려면 여전히 응답 순서와 식별자 계약이 필요합니다. 로컬 표식을 서버의 요청 식별자인 것처럼 사용하지 않았습니다.
