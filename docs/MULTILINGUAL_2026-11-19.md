# 다국어 화면 및 음성 언어 전환 — 2026-11-19

후속 타이머 작업으로 첫 PCM부터 시간을 재던 방식과 12초 후에도 계속 기다리던 방식이 변경됐습니다. 현재 시간 계산·종료·늦은 응답 처리 기준은 [음성 대기 개선 보고서](VOICE_WAIT_2026-11-19.md)를 참고하세요. 아래는 이 문서를 처음 작성한 작업의 기록입니다.

## 구현 범위

기존 메뉴/화면 정합성 수정이 커밋되지 않은 상태에서 이어서 작업했습니다. 앞선 수정은 보존했고, 기존 API와 장바구니·결제 프로토콜을 변경하지 않았습니다. 이번에도 커밋·푸시·PR·머지·배포하지 않았습니다.

- 한국어 `ko`, 일본어 `ja`, 스페인어 `es`, 태국어 `th`를 지원합니다. 제목 아래 기존 버튼 스타일로 선택 버튼을 추가했습니다. 선택 언어는 `voice-kiosk-language`라는 별도 localStorage 키에만 저장합니다. 저장소가 막혀도 메모리에서 전환하며 다른 저장소/주문 기록은 건드리지 않습니다.
- 기존 i18n 라이브러리가 없어 작은 표시 전용 번역 모듈을 추가했습니다. 한국어 원문을 기본값으로 두고 UI·오류·메뉴·옵션·분류·알레르기 번역을 프론트에서 관리합니다. 번역 API나 외부 번역 서비스를 호출하지 않습니다. 미등록 문구·새 서버 메뉴는 원문으로 표시합니다.
- React가 렌더한 트리의 텍스트와 접근성/이미지 설명을 번역합니다. DOM을 직접 바꾸지 않으며 이벤트 함수·ref·input value·option value·메뉴 ID·옵션 ID·주문 상태·인증 토큰은 번역하지 않습니다. 외부 SDK iframe과 동적으로 삽입한 결제 UI는 접근하거나 수정하지 않습니다.
- 메뉴·장바구니·영수증·추천·결제 안내·오류·KDS·관리자·로그인·상태 표시를 번역합니다. 현재 공개 메뉴 스냅샷의 17개 상품과 옵션/알레르기 이름을 포함합니다. 브랜드명/주문번호/사용자 ID/요청 경로와 기술 코드 등은 식별자로 보존합니다.
- 금액은 같은 원화 금액을 선택 언어의 Intl 형식으로 표시합니다. 환율이나 API 통화를 바꾸지 않습니다. KDS/관리자 로그 날짜는 선택 언어로 표시합니다. TTS에도 선택 언어의 문구와 locale을 전달하며 실제 음성 제공 여부는 브라우저/OS에 따릅니다.

## 음성 전환 및 대기 시간

- 기존 WebSocket의 수신 경로에서 JSON 객체를 검증하고 최상위 `language`만 읽습니다. 음성 시작이 완료된 후에만 자동 언어 전환합니다. `ko`/`ja`/`es`/`th`와 정확히 일치하는 문자열만 허용하며 미지원 코드, null/숫자/객체, 대소문자나 공백이 다른 값은 무시합니다.
- 언어를 먼저 반영한 다음 기존 `type: order` / `item` 처리로 이어집니다. 수동 선택 이후에도 다음 유효한 음성 응답에서 다시 전환할 수 있습니다. 메뉴 이름 매칭, 옵션 선택, 한 이벤트의 수량 처리, 결제 중 주문 반영 차단 등 기존 주문 동작은 변경하지 않았습니다.
- 첫 PCM 전송부터 3초 후 처리 중 안내, 한국어 5초/외국어 12초 후 터치 대체 안내를 표시합니다. 이후 PCM 프레임이 기존 타이머를 반복 연장하지 않습니다. 대기 중 수동 언어 변경 시 최초 시작 시각은 보존하며 새 기준까지 남은 시간을 계산합니다.
- 처음 화면이 한국어이고 응답 완료 전까지 언어를 알 수 없다면 5초에 터치 선택을 열되 음성 결과를 계속 기다립니다. 9초에 일본어 응답이 와도 정상 수신하고 기존 주문 처리에 전달합니다. 타이머는 소켓/마이크를 중단하거나 주문을 폐기하지 않으며 화면을 강제로 이동하지 않습니다.
- 지연 시 TTS를 새로 재생하지 않습니다. TTS가 마이크 전송을 일시 정지시키는 기존 에코 방지 기능 때문에, 긴 외국어 발화를 중간에 방해할 수 있기 때문입니다. 처리 결과에 대한 기존 TTS 및 에코 방지는 유지합니다.
- 사진 전송 주소가 설정돼 있으면 기존 터치 스냅샷 기능을 유지합니다. 언어 버튼을 누르는 동작은 스냅샷을 요청하지 않습니다. 응답 수신·음성 중지·언마운트 때 예약된 타이머를 정리합니다.

## 실제 AI 규격과 추가 확인 사항

사용자의 후속 지시에 따라 기존 음성 주문 메시지 구조와 수량 처리 로직은 변경하지 않았습니다. 새로 확인된 필드는 최상위 `language`뿐입니다.

읽기 전용으로 확인한 AI 저장소 main은 `bfdee3e938cf2c9db62dc8b9014d63d5a97416a7`입니다. 다음 내용은 **원격 소스 확인이며 실제 배포 버전 확인이 아닙니다.**

- [schemas.py](https://github.com/dku-voice/voice-ai-server/blob/bfdee3e938cf2c9db62dc8b9014d63d5a97416a7/app/schemas.py): VoiceOrderResponse는 `status`, `recognized_text`, `items`, `error_msg`, `language` 구조입니다. 항목은 `menu_id` 문자열, `quantity` 정수, `options` 문자열 목록입니다.
- [websockets.py](https://github.com/dku-voice/voice-ai-server/blob/bfdee3e938cf2c9db62dc8b9014d63d5a97416a7/app/api/websockets.py): PCM 청크 수신 후 `END` 텍스트로 분석을 시작하고, 언어는 최종 응답에 포함합니다.
- 현재 프론트는 기존 `type: order`, `item` 이벤트를 처리하고 실제 메뉴의 숫자 menuId 또는 기존 이름으로 매칭합니다. AI 코드의 `menu_id: "burger_01"` 등을 실제 메뉴 ID로 임의 연결하거나 옵션 문장을 optionId로 추측하지 않았습니다. `END`나 새로운 발화 종료 규칙도 추가하지 않았습니다.
- 기존 프론트의 주문 이벤트는 `createCartItem` 기본 수량 1로 한 번 추가합니다. 기존 수량 증감/동일 옵션 합산은 유지합니다. AI 항목의 quantity를 새로 해석하는 작업은 이번 범위에서 제외했습니다. 실제 음성 수량을 검증하려면 배포된 JSON 예시와 수량 의미를 먼저 확인해야 합니다.

AI 담당자에게 **실제 배포 응답 예시, type/item 유지 여부, menu_id와 실제 메뉴 ID의 대응, quantity/옵션 규격, 발화 종료/END 요구 여부**를 확인해야 합니다. 새로운 응답도 최상위 language가 유효하면 화면 전환은 가능하지만, 새 items 구조의 주문 자동 반영까지 구현했다고 볼 수 없습니다.

## 결제 UI 언어의 경계

자체 결제 화면·오류·버튼·영수증은 번역합니다. 토스가 제공하는 iframe·인증창·카드사/간편결제 앱의 내부 문구는 프론트 번역 모듈로 바꿀 수 없습니다. 기존 SDK와 결제 설정을 그대로 유지했고, 확인되지 않은 locale 파라미터를 넣거나 언어 변경 때 위젯을 재생성하지 않았습니다.

[토스 공식 안내](https://docs.tosspayments.com/en/integration-widget)와 [SDK 문서](https://docs.tosspayments.com/sdk/v2/js/payment-widget)상 결제 UI는 상점 설정/variantKey와 연관됩니다. 일본어·스페인어·태국어의 외부 결제 UI를 지원하는지와 필요한 계약/설정은 토스 측에 확인해야 합니다. 자체 UI의 4개 언어 지원과 외부 결제창의 지원 범위는 구분해야 합니다.

- `npm test`: **161개 통과**. 이전 149개 테스트를 포함합니다. 실제 메뉴 스냅샷 전체 번역, 동적 오류, 저장소 차단, 4개 버튼의 이벤트 핸들러, 화면 렌더링, 메뉴/옵션/수량/API 값 보존, 가상 시계의 5초/12초와 9초 후 응답을 검증했습니다.
- `npm run lint`, `npm run build`, `git diff --check`: 통과. CSS는 변경하지 않았고 빌드 CSS는 기존 `index-e5e3cd2d.css`와 같습니다. PCM/WASM/Worklet, API 경로·요청 body, 결제 승인·콜백·복구 모듈도 변경하지 않았습니다.
